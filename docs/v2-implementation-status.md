# 家庭記帳 v2：1–7 開發狀態

> 日期：2026-08-11
> 環境：Firebase dev；所有金額與名稱均為示範資料

## 已完成

1. **分類與帳戶**：收入／支出分類、圖示、排序、封存；現金、銀行、信用卡、投資與外幣帳戶；初始餘額、淨資產、帳戶明細與帳務調整。
2. **正式交易**：收入、支出、轉帳、手續費、日期補記、備註、帳戶／分類／專案選擇；所有明細使用同一套整版 UI 編輯或作廢。
3. **預算與專案**：每月／年度分類預算及加總；專案設定、預算、收支與明細，並同時納入整體報表。
4. **定期項目**：週／月／年規則、預設確認、自動入帳、提前顯示、略過、編輯與封存；固定 occurrence ID 防止兩台裝置重複入帳。
5. **代墊與分帳**：我替別人代墊、別人替我代墊、純代墊、自己的份額、多人不同金額、個別剩餘與部分收還款；收還款不重複計入收支。
6. **查看與報表**：首頁真實摘要、預算明細、全部交易、收支行事曆、收入／支出／淨資產趨勢、支出分類與帳戶／專案明細。
7. **同步與防護**：Google 成員登入、Firestore 即時同步、Rules 家庭邊界、文件 revision 衝突檢查、軟刪除／封存，以及手機左緣右滑返回。

## 驗證證據

- 31 項自動測試通過：舊版後端安全 5、帳務核心 12、v2 衍生計算 5、Firebase Auth／Rules 9。
- v2 lint 與 production build 通過。
- Firebase Hosting 實際驗證：新增、編輯、作廢支出；帳戶餘額與報表回算；多人代墊部分收款與收款明細作廢；預算、專案、定期、行事曆；390×844 手機版與 1280×720 電腦版。

## 下一階段

目前功能層可保留，但 UI 與先前逐頁確認的原型有明顯落差，尚未通過介面驗收。下一步先以 `docs/prototypes/family-finance-ui.source.html` 為唯一視覺基準，建立逐頁 parity checklist，依序修正首頁／記一筆、帳戶、更多設定、報表與行事曆，並以手機與電腦截圖逐頁比對。

UI 對齊完成後才製作「舊資料匯入預覽」。匯入必須先顯示筆數、日期範圍、帳戶／分類對應與新舊總額差異，確認後才寫入；舊站保持不動。
